# 21 全体に差し込む（2026-11-10）

抹茶のコレクションページの全体に、抹茶診断を差し込んだモック。案としての完成形（ユーザー 2026-11-10「案としては完成って感じでいこう！」）。本番にはまだ何も書いていない。

## ファイル

| ファイル | 中身 | いつ触るか |
|---|---|---|
| `01_全体のモック.html` | ページ全体。挨拶 → 飲み方のグラフ → 抹茶診断の入口 → 商品の札 #0〜#3 → 辻喜 → 番号の違い → オーナーから | ページの並びや、診断以外の文を変える時 |
| `抹茶診断/文言.js` | **診断の言葉と決め方の全部。** 四つの抹茶の値段・丸の数・短い文もここ | **診断の言葉を変える時は、ここだけ** |
| `抹茶診断/診断.css` | 診断の窓の見た目（頭は B「余白と明朝」） | 見た目を変える時 |
| `抹茶診断/診断.js` | 診断の仕組み（問いの順、絞り込み、結果の組み立て） | 問いの数や流れそのものを変える時 |

三つは別のファイルなので、言葉を直しても仕組みは壊れない。ページ側は、開くボタンに `data-yq-open` を付けるだけ。

## 文言.js の中の並び

1. 四つの抹茶（値段、丸の数、札の文、診断で出す文）
2. 診断の言葉（窓の頭、問い、選択肢、かぎかっこで引く言葉、控えに書く言葉）
3. 決め方（二問目での絞り込み、はじめて・飲んだことがある人の表、よく飲む人の表）
4. 結果の言葉（おすすめの文の型、飲み比べ、いつもと違う抹茶の理由、最後の一行）

`{n}` `{said}` のような波かっこは、仕組みが番号や選んだ言葉に差し替える。消さない。
`first` `kire` `milk` のような英字の鍵は仕組みが使う。変えない。

## 決まっていること（ユーザーの言葉）

- 診断は小さな窓で開く。ページは切り替わらない。無理に開かせない
- 「自分の意見が反映されておすすめされているっていう購入体験」
- 聞く順：はじめてか → 味の好み → 飲み方 →（よく飲む人だけ）今回はどんな抹茶を探しているか
- 結果は一つか二つ。「押し売りはしない感じ」
- 「番号ごとの飲み方は目安。味の好みで選んでいい」を最後に必ず言う
- 窓の頭は B。缶の下の棒は無し。「缶」ではなく「抹茶」と言う

## まだ仮のもの

- 決め方の表と、添える言葉（「ゆっくり味わう一杯なら」など）
- 挨拶、番号の違い、オーナーからの文
- 缶の絵（本番は実物の写真）
- グラフでは #1 はお薄だけ、#2 はお薄とお濃茶。診断ではミルクの人に #1・#2 が出ることがある（ユーザー「食い違いは別に大丈夫。こゆの見方もあるよという提案」）
